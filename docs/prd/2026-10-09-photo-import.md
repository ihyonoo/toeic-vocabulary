# PRD: 사진으로 단어 등록

- 작성일: 2026-10-09
- 상태: 확정 (spec-review 1회 반영, TRD 리뷰에서 R-54 호출 방식 변경)
- 바탕 문서: `docs/prd/2026-10-07-toeic-vocab-app.md`(이하 MVP PRD), `docs/design/2026-10-08-my-words.md`(이하 내 단어 메모)
- 요구사항 ID는 MVP PRD와 겹치지 않게 R-45부터, 성공 기준은 S-6부터 붙인다
- 10-10 변경: 7장의 배포 질문은 `docs/design/2026-10-10-devserver-deploy.md`가 닫았다
- 이 문서가 바꾸는 바탕 문서 내용: MVP PRD 5장 비목표의 "사진 업로드와 AI·OCR 단어 추출", 6장 제약의 "유료 외부 API를 쓰지 않는다", 7장 열린 질문의 추출 방식. 이 셋은 이 문서가 우선한다

## 1. 문제와 배경

- 단어 등록은 지금 Mac의 Claude Code 대화를 거쳐야 한다.
  - 사용자가 종이 사진을 대화에 첨부하면 Claude가 단어를 추출해 등록 API를 호출한다(MVP PRD 6장 등록 경로).
  - 학원 수업은 거의 매일 있고, 사진은 폰으로 찍는다. 그런데 등록하려면 매번 Mac 앞에 앉아 대화를 열어야 한다.
  - 내 단어(손글씨 노트)도 같은 경로라 Day 번호를 묻고 답하는 왕복이 매번 생긴다.
- 사용자는 이 기능을 위해 OpenAI API 크레딧(US$45 안팎, 캡스톤 예산 71,000원)을 샀다.
- 시험(12-13)까지 남은 수업일마다 등록이 반복되므로, 폰에서 바로 끝나지 않으면 등록이 밀리고 그날 학습도 밀린다.

## 2. 목표와 성공 기준

목표는 사용자가 폰 앱만으로 종이 사진에서 Day 등록까지 끝내는 것이다.

| ID | 성공 기준 |
|---|---|
| S-6 | Day 01 수업 단어 사진 2장(종이 111줄)을 올리면 미리보기가 111줄이다. 영어가 종이와 다른 줄이 0개이고, 뜻이 MVP PRD R-2 정규화 뒤 종이와 다른 줄이 0개다 |
| S-7 | Day 01 내 단어 사진 2장(손글씨 41줄)을 올리면 빠진 줄과 지어낸 줄이 0개이고, 영어가 사용자가 의도한 철자와 다른 줄이 2개(5%) 이하다 |
| S-8 | 사용자가 Claude Code 대화 없이 폰 앱만으로 사진 선택부터 등록 결과 확인까지 끝낸다 |
| S-9 | 사진 2장을 올리고([올리기]를 누른 때부터) 5분 안에 미리보기가 화면에 나온다 |
| S-10 | 처리 중에 앱을 완전히 닫았다가 다시 열어도 홈에 초안 줄이 남아 있고, 처리가 끝났으면 그 줄이 확인 대기로 보이며 누르면 미리보기가 열린다 |
| S-11 | 사진 2장 1회 처리 비용이 300원 이하다 |

**판정 방법**
- S-6, S-7, S-9, S-11은 사용자가 API 키를 넣은 뒤 Day 01 사진으로 한 번씩 잰다. 기준을 못 맞추면 한 번 더 재고, 두 번 다 못 맞추면 실패로 본다.
  - 측정한 초안은 등록하지 않고 버린다. Day 01은 이미 등록돼 있다.
- S-6, S-7의 정답은 종이다. 대조를 빠르게 하려고 등록 원본 파일을 쓴다.
  - 원본: 수업 단어 `data/import/day01.json`(111줄), 내 단어 `data/import/day01-mine.json`(41줄). 같은 사진에서 Claude가 종이 순서대로 만든 것이고, 저장소에 커밋하지 않는 `data/`에 있다.
  - 미리보기 줄과 원본 줄을 순서대로 짝짓는다. 다른 줄은 종이를 보고 판정하고, AI가 맞으면 다른 줄에서 뺀다.
  - 내 단어는 노트에 사용자가 틀리게 쓴 철자를 AI가 바르게 고쳤으면 맞은 줄이다(R-54).
- S-7의 허용치 2줄은 미리보기에서 손으로 고칠 만한 양으로 정했다. 0이 아닌 이유는 손글씨 인식이 확인되지 않았기 때문이다(6장).
- S-9의 끝은 초안 화면이 미리보기로 바뀐 때다. 5분은 처리 시간 추정치(6장, 2분 안팎)에 사진 줄이기·전송·화면 갱신 시간과 여유를 더한 값이다.
- S-11은 서버 로그에 남긴 입력·출력 토큰 수와 모델 단가로 계산하고, 환율은 1,450원으로 친다. 300원은 추정치(6장)의 2배다.
  - 300원이면 예산 71,000원으로 230회 넘게 처리한다. 시험까지 필요한 처리는 수업일 약 45일 × (수업 단어 1회 + 내 단어 1회)로 약 90회다.
- S-8, S-10은 사용자가 아이폰에서 직접 해 보고 확인한다.

## 3. 사용자와 시나리오

사용자는 본인 한 명이고 아이폰을 쓴다(MVP PRD 3장).

**시나리오 A: 수업 단어 등록**
1. 학원에서 단어 종이 두 장을 받아 폰으로 찍는다.
2. 집에 와서(배포 전에는 Mac과 같은 와이파이) 홈에서 사진 등록을 열고 두 장을 고른다. 묶음은 수업 단어, Day 번호는 제안된 번호를 그대로 둔다.
3. 올린 것을 확인하고(초안 화면이 열림) 앱을 닫는다.
4. 나중에 앱을 열면 홈에 확인 대기 초안 줄이 보인다. 미리보기에서 AI가 고친 철자와 채운 뜻을 훑고, 잘못 읽은 뜻 하나를 고친 뒤 등록한다.
5. 등록 결과(새 단어, 다른 Day에서 연결, 이미 있음, 내 단어에서 옮김)를 확인하고 그 Day로 학습을 시작한다.

**시나리오 B: 내 단어 등록**
1. 수업과 과제 중에 모르는 단어를 노트에 손으로 적는다.
2. 노트 사진을 올리며 묶음은 내 단어, Day 번호는 직접 입력한다.
3. 미리보기에서 AI가 철자를 고친 행의 원래 철자를 보고 맞는지 확인한다. 뜻을 안 적은 단어는 AI가 채운 뜻을 확인한다.
4. 등록한다.

**시나리오 C: 실패**
1. 사진이 흐리거나 API 오류로 처리가 실패한다.
2. 홈에서 실패 초안 줄을 열어 이유를 보고 버린 뒤, 다시 찍어 올린다.

## 4. 요구사항

### 올리기

| ID | 우선순위 | 요구사항 |
|---|---|---|
| R-45 | MUST | 홈 Day 목록 끝에 '사진으로 등록' 버튼을 둔다. 사진 등록은 여기서만 시작한다. 홈 상단 버튼(MVP PRD R-11)은 바꾸지 않는다.<br>- Day가 하나도 없으면 빈 상태 안내 아래에 같은 버튼을 두고, 안내 문구는 사진으로 등록하라는 내용으로 바꾼다.<br>- Day 목록은 오름차순이라 그날의 Day가 목록 끝에 생긴다. 버튼도 그 옆에 둔다 |
| R-46 | MUST | 한 번에 사진 1~5장을 올린다.<br>- 올리기 화면에서 사진을 한 장 또는 여러 장씩 더해 쌓는다. 더할 때마다 카메라 촬영과 사진 보관함 선택 중 고른다.<br>- 쌓인 사진은 번호가 달린 썸네일로 보이고, 하나씩 뺄 수 있다. 쌓인 순서가 종이 순서다. 순서를 바꾸려면 빼고 다시 더한다.<br>- 5장을 넘으면 더하지 않고 이유를 알린다.<br>- 5장은 하루 종이 2장과 노트 여러 쪽을 한 번에 올릴 여유다. 처리 시간과 비용은 장수보다 단어 수에 따라 늘어난다(6장) |
| R-47 | MUST | 올리기 전에 묶음과 Day 번호를 정한다.<br>- 묶음은 수업 단어와 내 단어 중 하나이고, 처음에는 수업 단어가 선택돼 있다. 묶음은 등록에만 쓰고 AI 처리에는 쓰지 않는다.<br>- 수업 단어의 Day 번호 기본값은 '가장 큰 번호 + 1'이다. 가장 큰 번호는 등록된 Day와, 처리 중이거나 확인 대기인 수업 단어 초안의 번호 중에서 고른다. 둘 다 없으면 1이다.<br>- 내 단어는 기본값이 없다. 번호를 넣기 전에는 올릴 수 없다.<br>- 올리기 화면에서 수업 단어로 바꾸면 기본값이 다시 채워지고, 내 단어로 바꾸면 번호 칸이 비워진다.<br>- Day 번호는 1 이상의 정수다. 없는 번호면 등록할 때 Day를 만든다 |
| R-48 | MUST | 아이폰 사진(HEIC 포함)을 받는다. 앱이 사진을 긴 변 2048px 이하 JPEG(품질 0.85)로 줄여서 보낸다. 2048px은 OpenAI가 고해상도 이미지를 처리하는 최대 변 길이다. 더 크게 보내도 줄여서 처리하므로 전송량만 늘어난다 |
| R-49 | MUST | 서버는 사진을 디스크에 저장하지 않는다. 임시 파일도 만들지 않고 메모리에서만 다룬다. AI 호출(다시 시도 포함)이 끝나면 사진을 버린다 |
| R-50 | SHOULD | 한 번 올리는 동작 안에서 [올리기]를 여러 번 눌러도 초안은 하나만 생긴다. 같은 사진을 다시 올리는 것은 막지 않는다. [등록]을 여러 번 눌러도 한 번만 등록된다 |
| R-51 | MUST | `OPENAI_API_KEY`가 없으면 사진 등록을 시작할 수 없고 이유를 보여 준다. 나머지 기능은 그대로 동작한다 |
| R-52 | MUST | 사진 전송이 끝나 초안이 생기면 초안 화면으로 넘어간다. 그 화면이 열린 것이 올라갔다는 표시다.<br>- 전송 중에는 '올리는 중'을 보여 준다.<br>- 전송이 실패하면 올리기 화면에 사진·묶음·번호를 그대로 둔 채 이유를 보여 주고, 다시 올릴 수 있다.<br>- 전송 중에 앱을 닫으면 초안이 생기지 않을 수 있다. 홈에 초안 줄이 없으면 다시 올린다 |

### 처리

| ID | 우선순위 | 요구사항 |
|---|---|---|
| R-53 | MUST | 초안이 생긴 뒤에는 서버가 처리를 이어 간다. 사용자가 화면을 떠나거나 앱을 닫아도 처리는 계속된다. 초안이 여러 개면 각각 따로 동시에 처리한다 |
| R-54 | MUST | AI는 사진마다 따로 동시에 불러 다음 규칙으로 단어를 뽑는다. 사진 한 장의 결과를 쌓인 순서대로 이어 붙인다.<br>- 종이의 단어 줄마다 한 항목을 만든다. 한 장 안에서는 종이 순서다.<br>- 겹치는 줄도 그대로 둔다. 종이에 반복된 줄과, 사진 경계에서 두 번 찍힌 줄 모두다. 중복은 등록 때 기존 규칙(MVP PRD R-4)이 처리한다.<br>- 제목, 날짜, 줄 번호, 쪽 번호처럼 단어가 아닌 것은 버린다.<br>- 뜻은 종이에 적힌 글자를 그대로 옮긴다. 종이의 `영어 [뜻, 뜻]` 형식에서는 대괄호를 빼고 `뜻, 뜻`으로 옮긴다.<br>- 품사는 MVP PRD R-1 표기 규칙을 따른다.<br>- 단어마다 토익 맥락의 짧은 영어 예문(15단어 이하)과 한국어 해석을 만든다.<br>- 종이의 철자가 명백히 틀렸을 때만 고치고, 고친 항목에 종이의 철자를 남긴다. 영국식 철자, 대소문자, 하이픈 차이는 고치지 않는다 |
| R-55 | MUST | 종이에 뜻이 없으면 AI가 채우고 채웠다고 표시한다. 품사는 학원 종이에 원래 없으므로(MVP PRD 1장) 예문처럼 항상 AI가 정하고 표시하지 않는다 |
| R-56 | MUST | 처리가 실패하면 초안이 실패 상태가 되고, 초안 화면에 이유를 보여 준다.<br>- 실패 사유: OpenAI API 오류, 시간 초과, AI 거절, 응답이 출력 한도로 잘림, 단어를 하나도 못 찾음, 처리 중 서버 재시작.<br>- 사진 한 장이라도 실패하면 나머지 사진의 호출을 끊고 초안 전체를 실패로 둔다.<br>- 시간 초과: 사진 한 장의 호출에서 4분 안에 응답이 없으면 실패다. 한 장의 처리 시간 추정치 약 2분(6장)보다 길게 잡았다. S-9의 5분은 성공 목표이고, 이 값은 실패로 판정하는 경계다.<br>- 일시 오류(속도 제한, OpenAI 서버 오류, 연결 끊김, 시간 초과)는 서버가 한 번 다시 시도한다. 그래서 실패까지 가장 오래 걸리면 약 8분이다.<br>- 응답이 출력 한도로 잘리면 받은 부분도 버리고 초안 전체를 실패로 둔다. 이유에는 단어가 많은 사진은 나눠 찍어 올리라는 안내를 넣는다.<br>- 처리 중 Mac이 잠들어 요청이 끊기면 위 사유 중 하나로 실패한다.<br>- 흐린 사진에서 일부 줄만 빠뜨린 경우는 감지하지 못한다. 미리보기에서 줄 수를 보고 판단한다.<br>- 실패한 초안은 버리기만 할 수 있다. 다시 처리하려면 사진을 새로 올린다 |

### 초안

| ID | 우선순위 | 요구사항 |
|---|---|---|
| R-57 | MUST | 초안은 여러 개 둘 수 있다. 홈 상단 버튼과 Day 목록 사이에 초안을 올린 순서대로 한 줄씩 보여 준다.<br>- 각 줄에는 Day 번호, 묶음, 상태(처리 중 / 확인 대기와 단어 수 / 실패)가 나온다. 실패 이유는 초안 화면에서 보여 준다.<br>- 홈의 초안 줄은 홈을 열 때의 상태다. 홈에 머무는 동안 저절로 바뀌지 않는다.<br>- 초안이 없으면 이 영역은 없다 |
| R-58 | MUST | 초안은 등록하거나 버릴 때까지 남는다. 서버를 다시 시작해도 남는다 |
| R-59 | MUST | 초안 줄을 누르면 초안 화면이 열린다. 처리 중이면 처리 중임을 보여 주고, 처리가 끝나면 화면을 다시 열지 않아도 미리보기나 실패 화면으로 바뀐다. 앱을 열 때 미리보기로 저절로 넘어가지는 않는다 |

### 미리보기와 등록

| ID | 우선순위 | 요구사항 |
|---|---|---|
| R-60 | MUST | 미리보기는 뽑힌 단어를 종이 순서로 보여 준다. 행마다 영어, 품사, 뜻이 보인다. 단어 수도 보여 준다 |
| R-61 | MUST | AI가 철자를 고친 행에는 종이의 철자를, 뜻을 채운 행에는 채웠다는 표시를 보여 준다. 이 표시는 AI가 한 일을 알리는 것이라, 사용자가 그 행을 고쳐도 남는다 |
| R-62 | MUST | 행을 눌러 영어, 품사, 뜻, 예문, 해석을 모두 고친다. 행을 지울 수 있다 |
| R-63 | MUST | 미리보기에서 Day 번호와 묶음을 바꿀 수 있다. 번호 조건은 R-47과 같다. 미리보기에서는 묶음을 바꿔도 번호를 그대로 둔다 |
| R-64 | MUST | 등록하면 기존 등록 규칙(MVP PRD R-4, 내 단어 메모의 수업 단어 우선 규칙)을 그대로 따른다.<br>- 영어나 뜻이 빈 행이 있으면 등록하지 않고 그 행을 알려 준다.<br>- 이미 있는 단어는 기존 품사·예문·해석을 유지하고 빈 칸만 미리보기 값으로 채운다. 미리보기에서 고친 품사·예문도 같다 |
| R-65 | MUST | 등록하면 결과를 보여 주고 초안을 지운다. 결과 화면에서 그 Day로 갈 수 있다.<br>- 결과는 새 단어, 다른 Day에서 연결, 이미 있음, 내 단어에서 옮김의 개수다.<br>- 미리보기 안에서 겹친 줄은 두 번째부터 '이미 있음'으로 센다. 그래서 네 개수의 합은 등록한 행 수와 같다 |
| R-66 | MUST | 처리 중, 확인 대기, 실패 초안 모두 버릴 수 있다. 확인을 한 번 거친다. 처리 중인 초안을 버리면 진행 중인 AI 호출을 끊는다. 끊기 전까지 쓴 비용은 돌아오지 않는다 |
| R-67 | SHOULD | 미리보기에서 고친 내용은 서버의 초안에 저장된다. 앱을 닫았다 열어도 고친 내용이 남는다 |
| R-68 | COULD | 처리 중 화면에 올린 뒤 지난 시간을 보여 준다 |

## 5. 비목표

- Day 화면에서 사진 올리기 (홈에서만 시작한다, R-45)
- 원본 사진 보관과 다시 보기
- 실패한 초안 다시 처리 (새로 올린다, R-56)
- 미리보기에서 행 추가, 행 순서 바꾸기. AI가 줄을 많이 빠뜨렸으면 버리고 다시 올리고, 몇 개면 등록 뒤 Claude Code 경로로 더한다
- 미리보기에서 기존 단어와의 중복 여부 미리 표시 (등록 결과로만 알린다, R-65)
- AI가 묶음(인쇄물/손글씨)이나 Day 번호를 판별
- 같은 사진을 다시 올리는 것 막기 (R-50)
- 내 단어로 새 Day 번호를 넣을 때 경고. 그 번호가 다음 수업 단어 기본값을 하나 밀어도 막지 않는다
- 처리 완료 알림(푸시)
- 사용 비용·토큰 화면, 앱 안의 비용 한도
- Claude API 등 다른 AI 제공자, 모델 고르기 화면
- 등록 API와 Claude Code 경로 제거 (그대로 남긴다)
- 배포 (별도 라운드)
- 등록된 단어의 품사·예문·해석을 앱에서 고치기 (MVP PRD 비목표 유지. 미리보기의 5칸 편집은 등록 전 초안에만 적용된다)
- 뜻 표기가 조금 다른 같은 단어를 하나로 합치기. 같은 단어 판정은 MVP PRD R-2 그대로이고, AI가 채운 뜻도 같다

## 6. 제약

- **일정과 인력:** 사용자 한 명과 Claude가 개발한다. 첫 사용 목표일은 10-10이다. 밀리면 R-68, R-67, R-63 순서로 뺀다. 기존 Claude Code 등록 경로가 남아 있어 그사이 등록은 막히지 않는다.
- **AI 제공자와 모델:** OpenAI API의 `gpt-6.1-sol`을 추론 강도 `low`로 쓴다.
  - 사용자가 산 OpenAI 선불 크레딧이 비용 상한이다. 앱에는 비용 한도를 두지 않는다.
  - Roboflow 비전 벤치마크(10-09 조회)의 OCR 점수가 `gpt-6-luna`보다 높다. 한글 손글씨 성능은 확인되지 않았다. S-6, S-7로 확인한다.
- **추정의 근거 (사진 2장, 단어 100개, 예문 포함):**
  - 입력: 사진마다 약 2,900토큰(2048px, 고해상도 처리 기준) + 지시문 약 1,000 → 2장 약 7,800토큰
  - 출력: 단어당 약 90토큰 × 100 = 약 9,000토큰. 추론 토큰은 `low`라 적다고 보고 따로 더하지 않았다
  - 비용: 입력 $2, 출력 $10(100만 토큰당) → 약 $0.11 → 환율 1,450원으로 약 150원
  - 시간: 출력 속도 약 50토큰/초(Artificial Analysis, 10-09 조회) → 사진 한 장(약 4,500토큰) 약 1.5분. 두 장을 동시에 부르므로 전체도 2분 안팎이다. 첫 응답까지 몇 초가 더 든다
  - 이미지 토큰 규칙은 OpenAI 문서에 이 모델 기준으로 나와 있지 않아, 바로 앞 세대의 규칙으로 계산했다
- **배포 뒤 시간 제한:** 배포하면 Cloudflare가 응답 없는 요청을 100~125초에 끊는다. 그래서 처리 결과를 요청 하나로 기다리는 방식은 쓸 수 없다.
- **데이터:**
  - 사진은 OpenAI로 보내진다. 요청마다 OpenAI의 응답 저장 기능을 끈다(Responses API의 저장 끄기 설정).
  - 그래도 OpenAI는 남용 감시를 위해 최대 30일 기록을 보관할 수 있다. 이 보관은 받아들인다. 계정 단위 무보존 계약은 쓰지 않는다.
  - API로 보낸 데이터는 사용자가 따로 동의하지 않는 한 OpenAI 학습에 쓰이지 않는다.
- **키 관리:** `OPENAI_API_KEY`는 `.env`에만 둔다. 사용자가 직접 넣고, 대화나 저장소에 남기지 않는다.
- **실행 환경:** 이번 라운드도 Mac 로컬에서 실행한다(MVP PRD 6장). 배포는 별도 라운드다.
  - 폰은 Mac과 같은 와이파이에 있어야 올릴 수 있다. 학원이나 이동 중 업로드는 배포 뒤부터 된다.
  - 처리는 Mac 서버에서 돈다. 처리 중에 Mac이 잠들면 실패할 수 있다(R-56).
- **공개 저장소:** 테스트는 실제 OpenAI API를 부르지 않는다. 테스트에 학원 단어 목록을 넣지 않는다(MVP PRD R-44).

### 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| Claude API | 사용자가 OpenAI 크레딧을 샀음 |
| `gpt-6-luna` (입력 $0.10, 출력 $0.50, 1회 약 10원, 1분 안팎) | 사용자가 OCR 정확도를 우선함 |
| 두 모델을 Day 01 사진으로 비교한 뒤 결정 | 사용자가 `gpt-6.1-sol`로 바로 정함 |
| 추출 결과를 확인 없이 바로 등록 | 오인식이 학습에 섞임 |
| 처리 중 화면에서 기다리기 | 앱을 나가면 처음부터 다시 올려야 하고 비용도 다시 듦 |
| 원본 사진을 등록 전까지 보관 | 사용자가 보관하지 않는 쪽을 택함 |
| Day 화면에서도 사진 등록 | 사용자가 홈 한 곳을 택함 |
| AI가 인쇄물·손글씨로 묶음 판별 | 판별이 틀리면 따로 고쳐야 함 |
| 종이에 있는 내용만 추출 (예문 없음) | 카드 뒷면이 비고, 지금 등록본과 달라짐 |
| 초안 하나만 허용 | 수업 단어와 내 단어를 연달아 올릴 수 없음 |
| 사진 전부를 한 번에 AI 호출 | 단어 100개가 넘으면 출력이 약 1만 토큰(약 3분 이상)이라 시간 제한 4분과 Node 기본 응답 대기 5분에 걸림. 장마다 따로 부르면 순서는 이어 붙이기만 하면 되고, 일부 실패는 전체 실패로 단순하게 처리함 |
| 수업 단어 기본 번호를 등록된 Day만 보고 정하기 | 밀린 이틀 치를 연달아 올리면 두 초안이 같은 번호가 되어 한 Day로 합쳐짐 |

# PRD: 토익 학원 단어장 웹앱 MVP

- 작성일: 2026-10-07
- 상태: 확정 (spec-review 1회 반영)

## 1. 문제와 배경

- 2026-10-07부터 토익 학원에 다닌다. 매일 과제로 단어 암기가 나오고, 단어는 A4 종이 두 장(「번역 연습 수업 단어」, 「번역 연습 과제 단어」)으로 받는다.
  - 10-07 분량은 두 장 합쳐 111줄이고, 겹치는 줄을 빼면 99단어다.
- 단어는 주로 이동 중이나 씻는 시간에 외운다. 매일 A4 종이를 들고 다닐 수는 없다.
- 이전에는 해커스 노랭이 단어책의 전용 앱으로 외웠다. Day별 목록, 영어/뜻 가리기, 카드 넘기기, 북마크 같은 앱 경험이 학습에 효과적이었다. 하지만 학원 단어는 그 앱에 넣을 수 없다.
- 종이 단어는 `영어 [뜻, 뜻]` 형식만 있다.
  - 품사·예문이 없다.
  - 같은 단어가 장 안팎에서 반복된다(예: technician, repair, receipt).
  - 같은 철자라도 뜻이 다르게 나오기도 한다(예: label [라벨을 붙이다] / label [라벨, 표지]).
- 과제가 이미 매일 나오고 있고 시험(12-13)까지 남은 기간이 짧다. 그래서 학습 기능을 먼저 쓸 수 있어야 한다.

## 2. 목표와 성공 기준

목표는 학원 종이 단어를 아이폰에서 노랭이 앱과 비슷한 방식으로 외울 수 있게 하는 것이다.

| ID | 성공 기준 |
|---|---|
| S-1 | 사용자는 종이 사진을 Claude에 넘기는 것 말고 할 일이 없다. 그 뒤 Day가 앱에 생기고, 종이 대비 빠진 단어가 0개다. 등록 뒤 목록 검토·정정은 이 기준 밖이다 |
| S-2 | Day 행이 화면에 보이는 상태에서, 홈 → 특정 Day 학습 시작까지 터치가 3번 이하다 (Day 선택 → 학습하기 → 학습 시작) |
| S-3 | Day 01(99단어)을 교재순과 랜덤 각각 반복 1회로 끝까지 넘겼을 때 빠지거나 두 번 나온 카드가 0개다. 아이폰 Safari 탭과 홈 화면 실행 양쪽에서 확인한다 |
| S-4 | 숨긴 단어가 Day·통합·북마크 학습 각각에서, 숨긴 직후와 앱을 다시 연 뒤 모두 0회 나온다. 같은 단어의 북마크·숨김 상태는 그 단어가 속한 모든 Day에서 같다 |
| S-5 | MVP를 처음 쓰기 시작한 다음 날부터 7일 동안, 학원 수업이 있는 날마다 그날 Day를 1회 이상 학습한다. R-13의 기록으로 확인한다. 이번 라운드는 집 와이파이 안 사용을 기준으로 하고, 이동 중 학습은 배포 라운드의 성공 기준으로 넘긴다 |

## 3. 사용자와 시나리오

사용자는 본인 한 명이다. 영어 기초부터 토익 850을 준비하는 학원 수강생이고, 아이폰을 쓴다.

**시나리오 A — 단어 등록과 정리**
1. 학원에서 단어 종이 두 장을 받는다.
2. 사진을 찍어 Mac의 Claude Code 대화에 첨부한다.
3. Claude가 단어를 추출하고 품사·예문·해석을 채워, 그날 Day로 등록 API를 호출한다.
4. 사용자는 Day 목록을 훑으며 이미 아는 쉬운 단어를 숨긴다. 종이에 없던 단어를 직접 추가하고, 잘못 들어간 뜻은 고친다.

**시나리오 B — 암기**
1. 홈에서 오늘 Day를 연다.
2. 뜻을 가린 채(영어만 보기) 목록을 훑다가, 모르는 단어는 뜻 칸을 눌러 확인하고 북마크한다.
3. 학습하기에서 랜덤 2회로 카드를 넘긴다.
4. 카드를 눌러 예문을 확인하고, 다 아는 단어는 카드에서 바로 숨긴다.

**시나리오 C — 몰아서 복습**
1. 주말에 통합 학습으로 지금까지의 모든 단어를 랜덤으로 넘긴다.
2. 시험 전에는 북마크한 단어만 모아 반복한다.

## 4. 요구사항

### 단어 데이터와 등록

| ID | 우선순위 | 요구사항 |
|---|---|---|
| R-1 | MUST | 단어는 영어, 품사, 뜻, 예문, 예문 해석을 가진다. 영어와 뜻은 필수이고 나머지는 비어 있을 수 있다. 품사 표기 규칙은 다음과 같다. 숙어·구는 `구`로 적는다. 뜻 항목들의 품사가 서로 다르면 뜻 순서대로 `동사, 명사`처럼 적는다 |
| R-2 | MUST | 철자와 뜻이 모두 같으면 같은 단어다. 비교 규칙은 다음과 같다. 철자는 앞뒤 공백을 지우고, 연속 공백을 하나로 줄이고, 대소문자를 무시한다. 뜻은 앞뒤 공백을 지우고, 연속 공백을 하나로 줄이고, 쉼표·세미콜론 앞 공백을 없애고 뒤 공백을 하나로 맞춘 뒤 글자 그대로 비교한다(뜻 항목의 순서가 다르면 다른 단어). 같은 단어는 한 Day 안에서 한 번만 나타나고, 여러 Day에 동시에 속할 수 있다. 북마크·숨김·수정·삭제는 그 단어가 속한 모든 Day에 똑같이 적용된다 |
| R-3 | MUST | Day는 번호로만 식별하며 제목은 없다. 한 Day에는 그날의 수업 단어와 과제 단어가 구분 없이 담긴다. Day 안 단어는 등록된 순서(이하 교재순)를 유지한다 |
| R-4 | MUST | 등록 API는 Day 번호와 단어 목록을 JSON으로 받는다. 경우별 동작은 아래와 같다.<br>- Day가 없으면 만든다. 이미 있으면 그 Day 끝에 붙인다.<br>- 처음 보는 단어는 새로 만든다.<br>- 다른 Day에 이미 있는 단어는 그 단어를 연결한다. 기존 값은 유지하고, 기존 값이 비어 있는 칸만 요청 값으로 채운다. 숨김·북마크 상태도 유지한다.<br>- 그 Day에 이미 있는 단어는 건너뛴다.<br>- 요청 안에서 같은 단어가 여러 번 오면 첫 번째만 쓴다.<br>- 영어나 뜻이 빈 항목이 하나라도 있으면 요청 전체를 거부하고 아무것도 저장하지 않는다.<br>- 응답에는 새로 만든 단어, 연결한 단어, 건너뛴 단어가 담긴다 |
| R-5 | MUST | Day 조회 API는 Day 목록(번호, 단어 수)을 돌려준다. Claude는 사용자가 번호를 지정하지 않으면 가장 큰 번호 + 1을 쓴다 |
| R-6 | MUST | API는 앱 비밀번호(R-42)와 같은 값으로 인증한다. 인증되지 않은 호출은 거부한다 |
| R-7 | SHOULD | 단어 수정 API로 단어의 모든 칸(영어, 품사, 뜻, 예문, 해석)을 고칠 수 있다. Claude가 예문을 바로잡거나 직접 추가한 단어의 빈 칸을 채울 때 쓴다. R-21과 같은 충돌 규칙을 따른다 |
| R-8 | SHOULD | Day 삭제 API로 잘못 등록한 Day를 지운다. 그 Day의 소속만 지우고, 그 결과 어느 Day에도 속하지 않게 된 단어는 함께 지운다 |
| R-9 | MUST | 10-07에 받은 두 장(수업 단어·과제 단어)을 Day 01로 등록한다 |

### 홈

| ID | 우선순위 | 요구사항 |
|---|---|---|
| R-10 | MUST | Day 목록을 Day 01부터 오름차순으로 보여준다. 행을 누르면 그 Day의 단어 목록으로 이동한다 |
| R-11 | MUST | 상단에 [통합 학습]과 [북마크] 버튼을 둔다. [통합 학습]은 목록을 거치지 않고 바로 학습 설정(R-25~R-29)으로 간다. [북마크]는 북마크 화면(R-24)으로 간다 |
| R-12 | SHOULD | Day 행마다 마지막 학습일(`MM-DD`)과 학습 횟수를 보여준다. 기록이 없으면 학습 전임을 표시한다 |
| R-13 | SHOULD | 학습 기록 규칙은 다음과 같다.<br>- 기록 시점: Day 학습에서 첫 바퀴를 끝낸 순간이다. 첫 바퀴의 마지막 카드가 화면에 나오거나, 숨기기 때문에 첫 바퀴를 벗어나는 순간 중 먼저 오는 쪽이다. 이때 횟수가 1 오르고, 마지막 학습일은 그 날짜(서울 시간)가 된다.<br>- 학습 한 번(세션)당 최대 1회 기록한다. 완료 화면의 다시 학습(R-38)은 새 세션이다.<br>- 통합 학습과 북마크 학습은 기록하지 않는다 |
| R-14 | COULD | Day 행에 단어 수(숨긴 단어 포함)를 보여준다 |

### 단어 목록 화면 (Day, 북마크 공통)

| ID | 우선순위 | 요구사항 |
|---|---|---|
| R-15 | MUST | 단어를 영어·뜻 두 칸 목록으로 보여준다 |
| R-16 | MUST | 오른쪽 위 버튼으로 보기 모드(둘 다 / 영어만 / 뜻만)를 바꾼다. 가려진 칸에는 '터치하세요'가 보이고, 그 칸을 누르면 그 칸만 드러나며, 다시 누르면 다시 가려진다. 드러낸 상태는 그 화면에 있는 동안 유지되고, 보기 모드를 바꾸면 모두 다시 가려진다 |
| R-17 | MUST | 보기 모드는 하나뿐이고, 목록 화면과 학습 화면이 같이 쓴다. 어느 화면에서 바꿔도 다른 화면에 적용된다 |
| R-18 | SHOULD | 보기 모드는 앱을 다시 열어도 유지된다 (기기에 저장) |
| R-19 | MUST | 행마다 북마크를 켜고 끌 수 있다 |
| R-20 | MUST | 행을 왼쪽으로 밀면 숨기기/숨김 해제가 나온다. 숨긴 단어는 목록에서 흐리게 보인다 |
| R-21 | SHOULD | 같은 밀기 메뉴에서 수정과 삭제를 한다.<br>- 수정: 영어·뜻을 고친다. 수정 결과가 이미 있는 다른 단어와 R-2 기준으로 같아지면 저장하지 않고 이유를 알린다.<br>- 삭제: 확인을 거친 뒤 그 단어를 모든 Day에서 지운다 |
| R-22 | SHOULD | Day 목록 끝의 '단어 추가'로 영어·뜻을 입력하면 그 Day 끝에 붙는다.<br>- 같은 단어가 다른 Day에 이미 있으면 그 단어를 연결하고 기존 품사·예문을 유지한다. 그 단어가 숨김 상태면 숨김을 푼다.<br>- 이 Day에 이미 있으면 추가하지 않고 이유를 알린다 |
| R-23 | MUST | 화면 하단에 [학습하기] 버튼을 둔다 |
| R-24 | MUST | 북마크 화면은 북마크한 단어를 교재순(R-39와 같은 정의)으로 모아, R-15~R-23과 같은 방식으로 보여준다. 단, '단어 추가'(R-22)는 없다. 이 화면에서 북마크를 끈 행은 화면을 떠날 때까지 목록에 남아, 실수로 끈 것을 되돌릴 수 있다 |

### 학습 (Day, 통합, 북마크 공통)

| ID | 우선순위 | 요구사항 |
|---|---|---|
| R-25 | MUST | 학습 설정에서 순서를 고른다: 교재순, 랜덤 |
| R-26 | SHOULD | 순서 선택지에 알파벳순을 더한다 |
| R-27 | MUST | 학습 설정에서 반복 횟수를 고른다: 1, 2, 3, 계속. '계속'은 사용자가 나갈 때까지 반복한다. 선택지는 사용자가 요청한 그대로다 |
| R-28 | MUST | 학습 설정은 처음에 교재순·1회가 미리 선택돼 있다. [학습 시작] 한 번으로 시작할 수 있다 |
| R-29 | SHOULD | 마지막으로 고른 순서·반복을 기억해 다음 학습 설정에 미리 선택한다 (기기에 저장) |
| R-30 | MUST | 랜덤은 바퀴마다 새로 섞는다 |
| R-31 | MUST | 카드를 한 장씩 보여준다.<br>- 왼쪽으로 밀면 다음, 오른쪽으로 밀면 이전 카드로 간다.<br>- 위치는 바퀴 안에서 표시한다(`12 / 99`). 반복이 2회 이상이거나 '계속'이면 몇 번째 바퀴인지도 표시한다.<br>- 바퀴의 첫 카드에서 이전으로 가면 앞 바퀴의 마지막 카드로 간다. 이때 앞 바퀴는 지나온 순서 그대로다.<br>- 첫 바퀴의 첫 카드에서는 이전으로 가지 않는다 |
| R-32 | MUST | 카드 앞면에는 영어·품사·뜻이 나오고 보기 모드가 적용된다. 학습 화면에도 보기 모드 버튼이 있다. 가려진 칸을 누르면 드러나고, 다시 누르면 다시 가려진다 |
| R-33 | MUST | 카드의 칸 바깥을 누르면 뒷면(예문·해석)으로 뒤집히고, 다시 누르면 앞면으로 돌아온다. 예문이 없으면 없다고 표시한다. 다른 카드로 가면, 처음 보는 카드든 돌아온 카드든 앞면이고 보기 모드에 따라 가려진 상태로 시작한다 |
| R-34 | MUST | 카드에서 북마크를 켜고 끌 수 있다. 북마크 학습 중에 북마크를 꺼도 이번 학습에서는 빠지지 않는다 |
| R-35 | MUST | 카드에서 숨기기를 누르면 바로 다음 카드로 넘어간다.<br>- 그 단어는 지나온 카드를 포함해 이번 학습의 모든 바퀴에서 빠지고, 바퀴 장수도 그만큼 줄어든다. 이후 모든 학습에서도 빠진다.<br>- 숨긴 카드가 바퀴의 마지막 카드였다면 다음 바퀴의 첫 카드로 가고, 마지막 바퀴였다면 완료 화면으로 간다 |
| R-36 | MUST | 숨긴 단어는 Day·통합·북마크 학습 어디에도 나오지 않는다. 학습할 단어가 0개면 학습을 시작할 수 없고 이유를 보여준다. 학습 중에 모든 단어를 숨기면 학습을 끝내고 이유를 보여준다 |
| R-37 | MUST | 마지막 바퀴의 마지막 카드에서 한 번 더 밀면 완료 화면이 나온다. [목록으로]를 누르면 Day·북마크 학습은 그 목록으로, 통합 학습은 홈으로 돌아간다 |
| R-38 | COULD | 완료 화면에서 같은 설정으로 다시 학습할 수 있다 (새 세션) |
| R-39 | MUST | 통합 학습은 모든 Day의 단어를 단어마다 한 번씩 담는다. 통합·북마크의 교재순은 Day 오름차순 → Day 안 순서다. 여러 Day에 속한 단어는 처음 나온 위치를 따른다 |
| R-40 | COULD | 학습 중에는 화면이 꺼지지 않는다. HTTPS 환경에서만 동작하므로 이번 라운드에는 구현만 하고, 동작 확인은 배포 뒤에 한다 |

|---|---|---|
| R-41 | MUST | 아이폰 세로 화면을 기준으로 한다. 검은 배경에 노랑·주황 포인트 색을 쓰고, 이모지는 쓰지 않는다 (앱 아이콘 포함) |
| R-42 | MUST | 비밀번호(`APP_PASSWORD`)로 앱과 API(R-6) 접속을 보호한다. 한 번 로그인하면 1년 유지된다. 홈 화면 앱에서 다시 로그인하는 번거로움을 줄이고, 시험 뒤에도 쓸 수 있게 하려는 기간이다 |
| R-43 | SHOULD | 아이폰 홈 화면에 추가하면 앱 아이콘이 생기고, 주소창 없는 전체 화면으로 열린다. 아이콘은 Claude가 만든 글자 로고다 |
| R-44 | MUST | 단어 데이터와 비밀번호는 저장소에 커밋하지 않는다. 테스트에서 단어 몇 개를 예시로 쓰는 것은 괜찮지만, Day 전체 목록은 커밋하지 않는다 |

## 5. 비목표

- 사진 업로드와 AI·OCR 단어 추출, Day 번호 추천·입력 화면. 이번에는 Claude가 등록 API로 넣는다
- 앱 안의 Day 생성·삭제 화면 (Day 삭제는 API로만 한다, R-8)
- 한 Day에서만 단어 빼기, Day 안 단어 순서 바꾸기
- 앱에서 품사·예문·해석 수정 (API로만 한다, R-7)
- 카드에서 숨김 실행 취소 (목록의 숨김 해제로 되돌린다)
- 통합 학습의 Day 범위 지정
- 발음 음원, 자동 넘기기, 재생 간격·음성 배속
- 복습하기, 간격 반복, 외움/모름 판정
- 이어서 학습하기 (학습 도중 나가면 위치를 저장하지 않는다)
- 단어 검색
- 노랭이식 학습률·복습률 %, 홈 상단 통계 원
- 수업 단어/과제 단어 구분
- 여러 사용자, 회원가입, 로그아웃, 비밀번호 변경 화면
- 오프라인 동작
- 백업
- 홈서버 배포와 Docker 구성 (다음 라운드)

## 6. 제약

- **인력과 일정:** 사용자 한 명과 Claude가 개발한다. 첫 사용 목표일은 10-08이다. 일정이 밀리면 COULD, SHOULD 순서로 뺀다. 시험은 12-13이다.
- **실행 환경:** 이번 라운드는 Mac 로컬에서만 개발·실행한다.
  - 폰은 Mac과 같은 와이파이에 있고 Mac이 깨어 있을 때만 접속할 수 있다.
  - 그래서 이동 중 사용과 화면 꺼짐 방지(R-40)는 배포 뒤부터 가능하다.
- **배포 전제:** 다음 라운드에 홈서버(x86 리눅스 노트북, Docker Compose)에 올리고, Cloudflare Tunnel로 외부에 연결한다.
  - 이번 라운드는 Mac 전용 의존성(네이티브 모듈 포함)을 쓰지 않는다. 빌드 산출물이 Node만으로 실행되는지까지 확인한다.
  - 배포할 때 Mac의 데이터(단어, 북마크, 숨김, 학습 기록)는 DB 파일을 그대로 옮긴다.
  - 홈 화면 아이콘과 기기에 저장한 설정은 주소가 바뀌므로 배포 뒤 다시 추가·설정한다.
- **등록 경로:**
  - API 호출 주체는 Mac의 Claude Code다.
  - 사용자는 사진을 Claude Code 대화에 첨부한다.
  - Claude는 저장소 루트에 있고 git이 추적하지 않는 `.env`의 `APP_PASSWORD`로 인증한다.
  - Day 번호는 사용자가 정한 번호를 쓰고, 없으면 R-5 규칙을 따른다.
- **공개 저장소:** GitHub 공개 저장소에 올린다. 학원 자료(단어 데이터)와 비밀번호는 커밋하지 않는다(R-44).
- **비용:** 이번 라운드는 유료 외부 API를 쓰지 않는다.
- **품사·예문 출처:** 종이에 없는 품사·예문·해석은 Claude가 생성하므로 가끔 틀릴 수 있다. 앱에서는 영어·뜻만 고친다(R-21). 예문 수정은 Claude에게 요청하고, Claude는 R-7로 고친다.

### 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| Anki·Quizlet 같은 상용 앱 | 사용자가 Day 구성, 가리기, 숨기기 등 원하는 동작을 직접 정하고 싶어 함 |
| 네이티브 iOS 앱 | 애플 개발자 계정이 연 $99이거나, 무료 계정이면 7일마다 재설치해야 함 |
| MVP에 사진 업로드·AI 추출 포함 | 학습 기능을 먼저 쓰는 쪽을 택함. 등록은 Claude가 API로 대신함 |
| 수업/과제를 Day 안 섹션으로 구분하거나 별도 Day로 분리 | 사용자가 하나로 합치는 쪽을 택함 |
| 종이 그대로 중복 유지, 또는 철자만 같아도 같은 단어로 보기 | 앞의 것은 카드·북마크가 중복되고, 뒤의 것은 뜻이 종이와 달라짐 |
| 뜻을 항목 집합으로 비교(순서 무시) | 종이 표기를 그대로 보존하는 쪽을 택함. 같은 장 안의 중복은 표기가 같아서 문자열 비교로 충분함 |
| 노랭이식 학습률 % | 본 단어 비율이라 외웠는지와 무관하고 금방 100%가 됨 |
| Day 목록 내림차순 | 사용자가 Day 01부터 오름차순을 택함 |
| Cloudflare Access 이메일 인증 | 홈 화면 앱에서 인증 화면이 Safari로 넘어가는 문제가 생길 수 있음 |
| 화면마다 보기 모드를 따로 기억 | 사용자가 모든 화면이 같이 바뀌는 쪽을 택함 |

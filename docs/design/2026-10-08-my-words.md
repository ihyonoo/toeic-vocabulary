# 설계 메모: 내 단어와 카드 보기

- 작성일: 2026-10-08
- 상태: 확정 (spec-review 1회 반영)
- 기준 문서: `docs/prd/2026-10-07-toeic-vocab-app.md`, `docs/trd/2026-10-07-toeic-vocab-app.md`
- 이 메모가 바꾸는 PRD 규칙: R-3, R-4, R-5, R-15, R-22, R-24, R-25~R-29, R-36, R-39. 충돌하면 이 메모가 우선한다

## 문제

- **내 단어:** 학원이 나눠 주는 종이 단어 말고도, 사용자는 수업을 듣거나 과제를 하다가 모르는 단어를 따로 정리한다.
  - 지금은 그 단어를 넣으면 종이 단어와 한 목록에 섞인다.
  - 종이 단어(학원 시험 범위)와 내가 정리한 단어를 따로 외울 수 없다.
- **카드 보기:** 목록에서 특정 단어를 자세히 보려면 학습을 처음부터 시작해야 한다. 목록에서 누른 단어부터 카드로 넘겨 보고 싶다.
- 학원 과제가 매일 나오므로 배포 전에 먼저 필요하다.

## 결정 1: 묶음

- 한 Day 안의 단어를 두 **묶음**으로 나눈다.
  - **수업 단어(`class`):** 학원이 나눠 준 종이 단어. PRD의 「수업 단어」·「과제 단어」 두 장을 모두 포함한다.
  - **내 단어(`mine`):** 사용자가 정리한 단어
  - 묶음은 등록할 때 지정한 값이다. 출처로 자동 판단하지 않는다.
- Day는 그대로 하나다. 묶음은 Day와 단어의 소속(`day_words`)에 붙는 속성이다. 같은 단어가 Day마다 다른 묶음일 수 있다.
- 한 Day 안에서 단어는 지금처럼 한 번만 나타난다(R-2). PRD가 기각한 "수업/과제 구분"과는 나누는 축이 다르다.
- 기존 단어는 모두 수업 단어가 된다.
  - 10-08 실제 DB를 확인했다. Day 01 하나, 99단어이고 모두 종이 등록과 같은 시각에 만들어졌다. 앱으로 넣은 단어는 없다.

### 넣는 법

- **앱의 '단어 추가':** 언제나 내 단어 묶음 끝에 붙는다. 기존 R-22의 연결·숨김 해제 규칙은 그대로다.
- **사진 등록:** Claude가 등록 API에 `section`을 담는다.
  - 학원 인쇄물이면 `class`, 사용자가 손으로 정리한 노트면 `mine`이다. 애매하면 사용자에게 묻는다.
  - `section`을 생략하면 `class`다. `null`이나 다른 값이면 400이다.
- **Day 번호:**
  - 수업 단어는 지금 규칙 그대로다(R-5).
  - 내 단어는 Claude가 등록하기 전에 매번 사용자에게 번호를 묻는다. 기본값이 없다.

### 겹침

같은 Day 안에서 같은 단어(R-2)가 두 묶음에 걸치는 경우다.

| 이미 있는 묶음 | 새로 넣는 경로 | 동작 |
|---|---|---|
| 수업 단어 | 앱 '단어 추가' (내 단어) | 409. "이 Day의 수업 단어에 이미 있어요." |
| 내 단어 | 앱 '단어 추가' (내 단어) | 409. "이 Day의 내 단어에 이미 있어요." |
| 수업 단어 | 등록 `mine` | 건너뜀(`skipped`) |
| 내 단어 | 등록 `mine` | 건너뜀(`skipped`) |
| 수업 단어 | 등록 `class` | 건너뜀(`skipped`) |
| 내 단어 | 등록 `class` | **수업 단어로 옮긴다(`moved`).** 종이가 우선이다. 수업 단어 묶음이 종이(시험 범위)와 같아진다. 위치는 그 수업 단어 등록 순서의 끝이다 |

- 등록 응답에 `moved: WordRef[]`를 더한다. Claude는 옮긴 단어를 사용자에게 알린다.

## 결정 2: Day 화면

- 위에서부터 수업 단어 묶음, 내 단어 묶음 순서로 이어서 보여준다. 한 화면에서 스크롤한다.
- 묶음마다 머리줄에 이름과 단어 수(숨긴 단어 포함)를 적는다. 예: `수업 단어 99`, `내 단어 12`.
  - 기존 목록 위의 `N단어` 줄은 머리줄로 대신한다.
  - 두 머리줄은 단어가 0개여도 늘 보인다. 0개면 "아직 없어요"를 적는다.
  - 머리줄은 목록 항목(`<li>`)이 아니다.
- '단어 추가' 버튼은 내 단어 묶음 끝에 있다.
- 묶음 안의 순서는 등록 순서다.
- **북마크 화면은 묶음을 나누지 않는다.** 지금처럼 한 목록이다. 두 묶음에 모두 속한 단어가 두 번 나오는 일을 피한다.

## 결정 3: 학습 설정의 묶음 선택

- 학습 설정에 묶음 선택(둘 다 / 수업 단어 / 내 단어)을 더한다. Day·통합·북마크 학습 모두에 있다.
  - 순서·반복 아래에 두고, 칩 이름은 "단어"다.
  - 처음 기본값은 '둘 다'다. 이후에는 마지막 선택을 기억한다(R-29와 같은 저장소).
  - 기억한 묶음에 학습할 단어가 0개인 화면에서는 '둘 다'로 미리 선택한다. "[학습 시작] 한 번으로 시작"(R-28)과 S-2를 지키기 위해서다.
  - 고른 묶음에 학습할 단어가 0개면 [학습 시작]이 꺼진다. 문구는 경우에 따라 다르다.
    - 그 묶음에 숨기지 않은 단어가 없다: "이 묶음에는 학습할 단어가 없어요."
    - 전체가 0개다: 기존 R-36 문구
- **교재순**
  - Day 안: 수업 단어 → 내 단어, 각 묶음 안은 등록 순서다. 화면과 같다.
  - 통합·북마크: 단어마다 (Day, 묶음 순위, 위치)가 가장 작은 소속을 첫 위치로 보고, 그 순서로 정렬한다. 묶음 순위는 수업 0, 내 단어 1이다.
  - 묶음을 고르면 그 묶음의 소속만으로 첫 위치를 정한다.
- **통합·북마크의 묶음 판정:** 지금 어느 Day에서든 그 묶음에 속해 있으면 포함한다. 두 묶음에 모두 속한 단어는 두 선택 모두에 나온다.
- **학습 기록(R-13):** 묶음과 관계없이 Day 학습의 첫 바퀴를 끝내면 기록한다. 내 단어만 학습해도 S-5의 "학습 1회"로 센다.

## 결정 4: 카드 보기

- Day 화면과 북마크 화면의 목록에서 행을 누르면, 그 단어부터 카드로 넘겨 본다.
  - **누를 곳:** 행에서 가림 칸, 북마크 버튼, 밀기 메뉴를 뺀 곳이다. 밀기 메뉴가 열려 있으면 누르면 메뉴가 닫힌다.
  - **카드 목록:** 그 화면 목록과 같은 단어, 같은 순서다(숨긴 단어 포함). Day 화면은 수업 단어 → 내 단어 순서다.
  - **넘기기:** 학습과 같다. 좌우로 밀고, 탭으로 가림 칸을 토글하거나 카드를 뒤집고, 보기 모드가 적용된다. 반복은 1회다.
  - **처음과 끝:** 첫 카드에서 이전으로 가지 않는다. 마지막 카드 다음은 완료 화면("다 봤어요" + [목록으로])이다. [다시 학습]은 없다.
  - **카드 버튼**
    - 북마크: 켜고 끈다.
    - 숨기기: 숨김을 켜고 끄는 토글이다(숨기기/숨김 해제). 카드는 목록에서 빠지지 않는다. 숨긴 카드에는 "숨긴 단어" 표시가 붙는다.
  - **학습 기록:** 남기지 않는다(R-13 대상 아님). 화면 꺼짐 방지는 학습과 같다.
  - **[뒤로]·[목록으로]:** 목록에서 왔으면 브라우저 뒤로 가기를 써서 목록의 스크롤 위치를 지킨다. 아니면 목록 주소로 간다.
- **주소:** `/study?scope=day&day=<n>&mode=browse&start=<wordId>`, `/study?scope=bookmarks&mode=browse&start=<wordId>`.
  - `mode=browse`에서는 `order`·`repeat`·`group`을 쓰지 않는다.
  - `start`가 목록에 없으면 첫 카드부터다. `start`가 숫자가 아니거나 `mode`가 `browse` 외의 값이면 400이다.
  - 북마크 카드 보기는 누른 단어가 그사이 북마크를 끈 행이어도 같은 자리에 넣는다(`getBookmarkedWords`의 `alsoId`).
  - 열린 밀기 메뉴를 닫은 바로 그 탭은 카드 보기로 이어지지 않는다(아이폰 메일과 같음).
  - [뒤로]를 연달아 눌러도 한 번만 돌아간다.

## 데이터

- 스키마 `user_version` 1 → 2
  ```sql
  ALTER TABLE day_words ADD COLUMN section TEXT NOT NULL DEFAULT 'class'
    CHECK (section IN ('class', 'mine'));
  ```
  - Node 25.9.0(SQLite 3.53.0)에서 빈 DB(0→2)와 행이 있는 v1 DB(1→2) 모두 동작함을 리뷰에서 실행으로 확인했다.
  - 배포 Node 24에서는 배포 때 다시 확인한다.
- 위치(`position`)는 지금처럼 Day 안에서 하나의 수열이다. 정렬할 때 묶음 순위(`CASE section WHEN 'class' THEN 0 ELSE 1 END`)를 위치보다 먼저 본다.
- **실제 DB 백업:** 새 빌드로 실제 서버를 처음 띄우기 전에 `data/vocab.db`를 `data/vocab.v1.db`로 복사한다. 첫 접근에 자동으로 마이그레이션되고 되돌리는 마이그레이션이 없어서다.

## 인터페이스 (시그니처만)

```ts
type Section = 'class' | 'mine';
type StudyGroup = 'all' | Section;

type Word = { ...기존; sections: Section[] };   // 지금 속한 묶음들, ['class', 'mine'] 순서. 모든 Word 응답에 담는다
type DayWord = Word & { section: Section };      // 그 Day에서의 묶음
type ImportInput = { day: number; section?: Section; words: ImportItem[] };
type ImportResult = { day; created; linked; skipped; moved: WordRef[] };
type StudyPrefs = { order: Order; repeat: Repeat; group: StudyGroup };   // 칸마다 따로 검증, 잘못되면 그 칸만 기본값

function getDayWords(db, day: number): DayWord[] | null;                 // 묶음 순위 → 위치
function getAllWords(db, opts: { includeHidden: boolean; group?: StudyGroup }): Word[];         // group 기본 'all'
function getBookmarkedWords(db, opts: { includeHidden: boolean; group?: StudyGroup }): Word[];
function countStudyableWords(db): Record<StudyGroup, number>;
function addWordToDay(db, day: number, input: { english: string; meaning: string }): { word: DayWord; result: 'created' | 'linked' };
function setSection(db, day: number, wordId: number, section: Section): DayWord;    // Claude 정정용
function createSession(words, opts: { order; repeat; startId?: number }, rng?): SessionState;  // 카드 보기 시작 위치
```

| API | 내용 |
|---|---|
| `POST /api/days` | 본문에 `section`(선택). 응답에 `moved` |
| `GET /api/days/{n}` (신규) | `200 { day, words: DayWord[] }`. Claude가 단어 id를 찾아 예문을 채우거나 묶음을 바로잡을 때 쓴다. 없으면 404 |
| `PATCH /api/days/{n}/words/{id}` (신규) | 본문 `{ section }`. 그 Day 소속의 묶음을 바꾼다. 성공하면 `200 { word: DayWord }`, 소속이 없으면 404, 값이 잘못되면 400 |
| `POST /api/days/{n}/words` | 응답 `word`가 `DayWord`(언제나 `mine`). 409 문구는 겹침 표 |

- `/study` 쿼리
  - `group=all|class|mine`을 `repeat` 뒤에 붙인다. 없으면 `all`이다.
  - `mode=browse`, `start`를 더한다.
  - 그 밖의 값은 400이다.
- `StudySheet`의 prop은 `studyableCounts: Record<StudyGroup, number>`다.
  - 홈: 서버의 `countStudyableWords`
  - Day: 로컬 목록을 `section`으로 센다
  - 북마크: 로컬 목록(`bookmarked && !hidden`)을 `sections`로 센다

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 내 단어를 별도 Day로 만들기 | 사용자가 Day는 같게 하고 안에서 나누기를 원함 |
| 앱 추가 시 겹치면 내 단어로 옮기기 | 수업 단어 목록이 종이와 달라짐 |
| 겹치면 두 묶음에 모두 두기 | '둘 다' 학습에서 한 번만 나오게 하는 규칙이 복잡해지고 R-2를 깸 |
| 종이를 나중에 받았을 때 내 단어에 그대로 두기 | 수업 단어만 학습하면 시험 범위 단어가 빠짐. 사용자가 종이 우선을 택함 |
| 내 단어 Day 기본값을 가장 최근 Day나 새 Day로 | 사용자가 매번 번호를 묻기를 택함. 새 Day는 다음 종이 번호를 밀어냄 |
| 통합·북마크 학습에는 묶음 선택을 두지 않기 | 사용자가 모든 학습에 두기를 택함 |
| 북마크 화면도 묶음별로 나누기 | 두 묶음에 속한 단어가 두 번 나옴 |
| 묶음을 단어(`words`)의 속성으로 두기 | 같은 단어가 Day마다 다른 묶음일 수 있음 |
| 카드 보기 끝에서 멈추기·처음으로 돌기 | 사용자가 완료 화면을 택함 |
| 묶음 선택을 화면 종류별로 따로 기억 | 저장 칸이 세 배가 됨. 0개일 때 '둘 다'로 여는 규칙으로 충분함 |

## 비목표

- 앱에서 단어를 다른 묶음으로 옮기기 (Claude가 `PATCH /api/days/{n}/words/{id}`로 한다)
- 한 Day의 한 묶음만 지우기. `DELETE /api/days/{n}`은 그 Day의 내 단어까지 지운다. README에 경고한다
- 내 단어만 따로 보는 목록 화면, 묶음 접기·펼치기, 묶음 이름 바꾸기, 세 번째 묶음
- 홈 Day 행·`GET /api/days`의 묶음별 단어 수, 묶음별 학습 기록
- 학습 설정에서 묶음별 단어 수 표시
- 앱에서 내 단어의 품사·예문 입력 (Claude가 `GET /api/days/{n}`로 찾아 `PATCH /api/words/{id}`로 채운다)
- 앱에서 수업 단어 추가
- 카드 보기의 순서 바꾸기·반복·학습 기록
- 배포 (다음 작업)

## 가정

| 가정 | 틀리면 깨지는 것 |
|---|---|
| 앱에서 추가하는 단어는 언제나 내 단어다 | 수업 단어를 손으로 넣을 길이 없다. 그때는 추가 시트에 묶음 선택을 넣는다 |
| 손글씨 노트와 학원 인쇄물을 사진으로 구분할 수 있다 | 잘못 넣으면 Claude가 `PATCH /api/days/{n}/words/{id}`로 고친다 |
| 목록에서 행을 누르는 동작이 가림 칸 토글과 헷갈리지 않는다 | 가림 칸은 점선 상자라 구분된다. 실기기에서 어색하면 카드 보기 진입을 다른 방식으로 바꾼다 |

## 완료 기준

- 마이그레이션 뒤 기존 Day의 단어가 모두 `class`이고, 화면 순서가 그대로다 (v1 파일 DB → v2 단위 테스트)
- 겹침 표의 여섯 경우가 표대로 동작한다 (단위 테스트)
- '둘 다' 학습에서 두 묶음에 걸친 단어가 한 번만 나오고, 묶음별 교재순이 정의대로다 (단위 테스트)
- Day 화면에 두 묶음과 머리줄이 보이고, 추가한 단어가 내 단어 끝에 붙는다 (E2E)
- 묶음 선택이 Day·통합·북마크 학습에 적용되고, 기억·'둘 다' 대체가 동작한다 (E2E)
- 목록에서 행을 누르면 그 단어 카드부터 보이고, 끝에서 완료 화면이 나오며, 학습 기록이 늘지 않는다 (E2E)
- 기존 단위·E2E 테스트가 통과한다. 바뀌는 기대값은 `countStudyableWords` 반환형과 단어 추가 409 문구 두 곳이다

## 구현 순서

1. 마이그레이션 v2와 마이그레이션 테스트
2. repo: `section` 등록·겹침·`moved`, 정렬, `sections`, 단어 추가 409, 묶음별 집계, `setSection`, Day 단어 조회
3. API: `POST /api/days`의 `section`, `GET /api/days/{n}`, `PATCH /api/days/{n}/words/{id}`
4. Day 화면의 두 묶음과 단어 추가
5. 학습 묶음 선택: `StudySheet`, `studyPrefs`, `/study`의 `group`, 홈·북마크 집계
6. 카드 보기: 세션 시작 위치, `/study`의 `mode=browse`, 행 누르기, 완료 화면, 뒤로 가기
7. 문서: README 등록 절차(`section`, Day 번호 묻기, `moved` 보고, Day 삭제 경고), PRD·TRD 머리말에 이 메모 우선 표시, 진행 기록
